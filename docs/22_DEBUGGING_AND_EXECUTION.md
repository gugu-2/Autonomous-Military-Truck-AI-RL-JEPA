# Execution and Debugging Guide

Debugging a 7-layer hybrid AI stack (PyTorch + ROS 2 + VLA) is fundamentally different from debugging a standard web application. You cannot simply use `print()` statements when dealing with 10-dimensional tensors running at 84 FPS.

## 1. Visualizing the JEPA Latent Space

If the car is crashing in simulation, the first step is to determine if it is a **Perception failure** (it didn't "see" the wall) or an **Action failure** (it saw the wall but steered into it anyway).

* **Tool:** `scripts/visualize_jepa.py`
* **Usage:** Run this script while the main AI is running. It hooks into the PyTorch memory stream and decodes the latent `s_t` vector back into a pixel heatmap.
* **Analysis:** If the heatmap shows a red blob over a pedestrian, the JEPA engine is working. The fault lies in the RL Controller. If the heatmap is blank, your camera drivers or ViT Encoder are failing.

## 2. Debugging the DreamerV3 RL Agent

The RL agent operates entirely in latent math, making it highly opaque. 

### Checking the Hazard Energy Veto
If the car is suddenly slamming the brakes for no reason (Phantom Braking):
1. Check the logs: `tail -f logs/safety.log`
2. Look for `HazardEnergy` spikes. 
3. If $E(t+k) > 0.70$, the JEPA predictor is hallucinating dangerous futures. 
   * **Fix:** You likely need to fine-tune the JEPA predictor on more benign dashcam data, as it has become overly pessimistic.

### Checking Action Saturation
If the car feels sluggish or fails to turn sharply:
1. Log the Actor network outputs: `print(action_dist.mean)` inside `actor_critic.py`.
2. If the outputs are permanently pegged at `-1.0` or `1.0`, your reward function gradients have exploded, causing the Tanh squashing function to saturate.
   * **Fix:** Lower the learning rate and check if you are dividing by zero in your custom reward function.

## 3. Debugging the Alpamayo VLA (Reasoning Module)

If the car fails to obey complex hand signals from a soldier:
1. Open `logs/alpamayo_reasoning.log`.
2. Look at the `SceneDescriptor` prompt generated by the AI. Did the camera successfully convert the pixels into text? (e.g., "A soldier is waving his arms").
3. Look at the `IntentParser` output. Did Alpamayo output `<intent>PROCEED</intent>` instead of `STOP`?
   * **Fix:** If the text prompt was wrong, the vision-text alignment is broken. If the text prompt was correct but the intent was wrong, you need to adjust the prompt engineering in `alpamayo_client.py` to give stricter instructions.

## 4. CPU Watchdog Triggering

If the system crashes with `FATAL: Watchdog Triggered. Emergency Brake applied.`
* **Cause:** Your PyTorch forward pass took longer than 12 milliseconds. 
* **Debugging:** 
  1. Use PyTorch Profiler to find the bottleneck.
  ```python
  import torch.autograd.profiler as profiler
  with profiler.profile(use_cuda=True) as prof:
      output = jepa_model(input)
  print(prof.key_averages().table(sort_by="cuda_time_total"))
  ```
  2. If the `attention` layer is the bottleneck, ensure `gradient_checkpointing` is enabled and `FlashAttention-2` is properly installed in your environment.
